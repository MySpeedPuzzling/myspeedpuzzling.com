# Events, series, organizations and competitions

Loaded automatically when you read or edit files of this area (the events agenda, series/editions, organizations and drafts, competition management, round results, online competitions, the partner finder and the event results import). Read on purpose when planning work here before touching code. Each entry is the as-built summary; its doc under `docs/features/` is the design of record - read it before changing behaviour, and update both when behaviour changes.

- **Partner finder (pairs and teams)**: `docs/features/partner-finder.md` — free for everyone: puzzlers going to an in-person event list themselves (`partner_listing`: on my own / a group of N, looking for a pair and/or a team or "need M more", preset "Good at" chips `PartnerStrength` ≤ 4 + ≤ 5 custom chips (a custom chip folding equal to a preset label in any locale becomes the preset, `PartnerStrengthNormalizer`), languages, goal, note ≤ 200). Eligibility = one rule `PartnerFinderEligibility::SQL_QUALIFIES` (the marketplace rule + has a slug + a duo/team round or no rounds; PHP pre-check `mightQualify()` pinned against it). Listing marks you going on plain events (`PartnerFinderAttendance` = the shared self-join `CompetitionSelfJoin`, never takes anyone off the organiser's list; managed registration: no spot needed). Pages `event_partners` / `edition_partners` (one listings statement, guests a teaser only, `noindex`), gate `partner_finder` (`/en/partner-finder`, footer link, 1 statement), event page card `_partner_card.html.twig` (4 states, `HintType::PartnerFinderCard`, signed-in +1 statement) + "Find a partner (N)" button, `/en/events` tag rides on `GetEventGoingCounts`. "I'd like to puzzle with you" = `partner_request` → notification + async e-mail naming the sender (`player.partner_finder_emails`, one-click unsubscribe), the owner's Reply opens an accepted chat (`StartConversation::$partnerRequestId`, checked in the handler); blocks hide listings both ways and a block is silent. Auto-close on leaving + cron `myspeedpuzzling:close-partner-listings` (event over, entered in a pair/team entry). Phase 2: "Found my partner" may name who (`PartnerTeamUpCandidates` = exchanged a request, still listed) → `PartnerTeamedUp` asks them to close theirs (never closed for them), co-member picker (`partner_co_members_controller.js`, newly added told once - `PartnerGroupMember`), "N found a partner here" (event CTE), daily `myspeedpuzzling:remind-partner-listings` = "Still looking?" once per listing, event in 2-14 days and listing ≥ 5 days old (`reminded_at`)
- **Live-event strip (removed 2026-10-23)**: `docs/features/live-event-strip.md` — the WJPC 2026 "Now live" link at the top of the sticky header (`base.html.twig`, `.competition-panel-info`, `live_event_strip` in 6 locales, ended by `now() < date(…)`); the doc keeps the full markup, styles and texts - copy it from there for the next live event
- **Participants spreadsheet**: `docs/features/competitions-management/participants-spreadsheet.md` (§13 = what was delivered and why, then the client architecture) — the organiser's sheet `participants_sheet` (`/en/participants-sheet/{competitionId}`): People tab + one tab per round (pairs/teams = one row per pair/team, solo rounds too) with results / table / qualified columns, registration columns for managed events, phone lists. **Every participant/entry/team write of the sheet is one message `ApplyParticipantSheetChanges`** (field-level changes with `from`, three-way per change, a group is atomic, net diff applied through the import's `ParticipantImportApplier`, rules shared with the import in `ParticipantRules`, under `CompetitionParticipantsLock`, receipts with the acting player = idempotency + change trail); results/table/qualified cells go through `RecordRoundResults` / `AssignTableNumbers` only; registration actions through the existing messages (`participants_sheet_registration`). Client: plain ES modules `assets/participants_sheet/` + the lazy `participants_sheet_controller.js` - an open editor's `from` is what it showed when it opened (never the model at commit), every refusal visible (`context.notify`). The old participants page and `manage_round_teams` redirect to it. Expected team size `competition_round.team_size` (team rounds only)
- **Round results**: `docs/features/competitions-management/round-results.md` — public ranking per competition round at `/en/events/{slug}/results/{roundSlug}` (+ `/en/series/{s}/{e}/results/{roundSlug}`). A time's round is **derived, never picked**: competition + puzzle + solo/duo/team (`SolvingTimeRoundResolver`), no date check; invariant = one round per category per puzzle per competition (`PuzzleAlreadyInCompetitionRoundCategory`). **Transaction gotcha:** handlers only persist, so time add/edit set `competitionRound` in PHP before flush, while round-side changes record `CompetitionRoundsChanged` → `RoundResultsReconciler` on postFlush (routed `sync`). Earliest time per player/team counts. **Exception: an imported event result keeps the round its import gave it** (`PuzzleSolvingTime::keepsItsRound()` / `SolvingTimeRoundResolver::SQL_ROUND_IS_DERIVED`, honoured by the resolver and both reconciler statements) - a pair at a teams event is ranked in the teams round (event results import D10). Round slugs kept on rename; `myspeedpuzzling:backfill-round-slugs` + `myspeedpuzzling:reconcile-round-results` (cron in lily.srv)
- **Events through the internal API**: `docs/features/internal-api.md` §"Competitions and events" — Claude Code creates/edits competitions, rounds, round + competition (tag) puzzles and adds missing puzzles (approved, no photo: `AddApprovedPuzzle`) over `/internal-api/competitions|rounds|puzzles`, through the web forms' messages and validation (`CompetitionFormData`/`CompetitionRoundFormData`). **A rename keeps the slug** - in the web forms too (events, editions, series); only an explicit `slug` changes it (API: unique or 409; web edit forms: the "URL" field, `CompetitionUrlField`, clash = form error), no redirect from the old one; `"isOnline": true` clears the location only - an online event keeps its (optional) dates, like the web form; approving a competition its reviewer player created skips the e-mail (`ApproveCompetition::$notifyCreator`, false only from the API); round `startsAt` in UTC (no offset = the country's zone); round puzzles = whole list in one message (`SetCompetitionRoundPuzzles`) with the one-round-per-category invariant checked first (409, nothing changes); a round with results is never deleted (409); competition puzzles = its tag's puzzles (shared tag → 409). Every 4xx under `/internal-api/` is JSON (`InternalApiErrorResponseSubscriber`), every write is logged on channel `internal_api_audit` (`InternalApiAuditSubscriber`, own prod handler) - both match the **decoded** path like the firewall (`InternalApiAuthenticator::isInternalApiRequest()`); expected 409s are logged at info (`config/packages/framework.php`)
- **Events page**: `docs/features/events-page/README.md` (+ `implementation-plan.md`) — `/en/events` is one agenda of **occurrences**: one-time events and series editions together (`GetEventOccurrences`, one statement over `IsCompetitionPubliclyVisible::SQL_CONDITION`; one-time events and editions alike are dated by their first round, else `date_from`; rounds more than 2 days apart (outside a declared span of ≤ 7 days) are separate **sessions** = one dated occurrence each, linking `#round-<id>`; a span over 31 days its rounds do not define is ongoing, never live - `OccurrenceDates::sessions()` is the one dating rule, also for the archive, the sitemap's archive years and "You organize"), grouped by month by `EventsPageBuilder` (several editions or sessions of one series in a month = one row with date chips; "Live" with the shared pulsing `.live-dot`, "Date to be announced" = undated in person, "Ongoing" = undated online one-time events + long spans without rounds; past editions roll up to one line per series and year). Search, scope chips (Everywhere default for everyone, always; online counts under Online only) and the `?view=calendar` month grid run in the browser over an index embedded in the page (`EventsIndexFactory` + `assets/events_index.js`, folded like `SearchText::fold()`), so guest HTML stays shared; organization names (public ones) are in the search; drafts are nowhere on the page (admins included). Every date comes from an ICU skeleton in the page's locale, never a hand-written pattern (`EventsPageDates`: Twig `|events_date('yMMMd')` / `events_date_range()`; browser `formatDate()` / `formatDayRange()` - same text, pinned by `EventsIndexScriptTest`; English = en-GB). Follow a one-time event, a whole series or an organization (`followed_competition`, `FollowCompetition`/`UnfollowCompetition`, stateless CSRF `event_follow`) → "Your events" = going + followed + next edition of followed series (+ each followed organization's next dates), live/coming only. Organisers/maintainers get "You organize (n)" (`organized_events`, `/en/you-organize`) and one lazily loaded ⋯ menu per row they may manage (`event_manage_menu`, one Turbo Frame; admins approve/reject unapproved items there). Year archive `events_archive` (`/en/events/archive/{year}`, indexable, in the sitemap); old `?timePeriod`/`?showCalendar` URLs redirect (`LegacyEventsQueryRedirect`). Statement budget pinned by `EventsPageQueryBudgetTest` (guest 3, signed in 8, admin 9, archive 1). The series, edition and event pages are built from the same parts in `templates/event_parts/` (+ `_event-parts.scss`) - series = `GetEventOccurrences::forSeries()` → `SeriesPageBuilder`, edition/event = `RoundsTimelineBuilder` (`#round-<id>` rows), times in the event's zone via `event_time()`, budgets in `DetailPagesQueryBudgetTest` - see `docs/features/events-page/detail-pages.md`; a change to a shared part changes all four pages
- **Event types**: `docs/features/events-page/event-types.md` — optional "What kind of event" (`Value\EventType`: competition, marathon, workshop, casual puzzling, puzzle swap; several allowed) as jsonb `event_types` on `competition` + `competition_series` (`[]` = not set, no backfill; written only via `changeEventTypes()`); an edition without its own shows its series' (saved equal to its series' = stored `[]`); shown only when not a plain competition (`EventTypes::shownOf()`): row tags, search words, byline, organization cards; internal API `eventTypes` (left out = unchanged), public API v1 untouched
