# Collections, marketplace and lending

Loaded automatically when you read or edit files of this area (sell/swap, listing requests, wishlist and borrowing, bulk selection on puzzle lists and the data export). Read on purpose when planning work here before touching code. Each entry is the as-built summary; its doc under `docs/features/` is the design of record - read it before changing behaviour, and update both when behaviour changes.

- **Marketplace**: `docs/features/marketplace/` — Centralized marketplace, messaging, ratings, shipping settings, admin moderation
- **Marketplace at events**: `docs/features/marketplace/11-events.md` — sellers mark listings they are **bringing** to an in-person event (`sell_swap_list_item_event`, kept after the event/leaving, hidden on read); **"Ask to bring it"** = the rest of a going seller's published list (derived, nothing stored). A *marketplace event* = in person, publicly visible, dated, not over - one rule `GetMarketplaceEvents::SQL_QUALIFIES` (+ static `sqlPlayerGoing()`), standalone events and editions alike. Event page card E2 (`_event_offers.html.twig`, one query, none on non-qualifying events), marketplace event select + bringing-first list + labels (LATERAL on the page rows only), picker `event_offers_picker` (also the F1 step after "I'm going" for members with listings; others get the `EventJustJoined` flash = highlighted card), "Bring to event" chat action + pre-filled contact message, banner `HintType::MarketplaceAtEvents`. New labels use the locale-aware Twig `event_dates()`. All 6 locales
- **Sell/swap requests (ask a seller for several puzzles)**: `docs/features/marketplace/12-listing-requests.md` — a signed-in buyer ticks listings on somebody's sell/swap list or the marketplace (`listing_selection_controller.js` + `assets/listing_selection_store.js`: sessionStorage per player, survives Live re-renders/paging - controller + bar outside the Live component, checkbox labels `data-live-ignore`) → sheet `listing_ask_sheet` grouped per seller (totals per seller currency, own listings offered in exchange for swaps, note ≤ 500) → `AskForListings` (one `listing_request` per seller, `listing_request_item` per listing with a copy of type/price/currency/condition, `listing_request_offer`; one rule `GetRequestableListings` - block either way/secret = unavailable, own/reserved for somebody else/already asked flagged, unpublished OK; ≤ 10 sellers / 30 listings, limiter `listing_request`, idempotent send id, `custom_listing_request_item_one_open`) → notification + e-mail (`player.listing_request_emails`) → seller answers per listing on `listing_request_detail`: yes = `ListingReservation::reserve()` for the buyer (refused while reserved for somebody else) + accepted chat (`StartConversation::$listingRequestId`), gone (+ off the list), declined; "Mark as sold to {buyer}" = existing sold flow. **Every handler that sells or deletes a listing calls `ListingRequestCloser::listingsGoing()` before the delete** (sold to the buyer = sold, else unavailable + the buyer told); withdraw releases only a reservation the request made; daily `myspeedpuzzling:expire-listing-requests` (waiting after 14 days, never a yes; also closes orphans with a warning). Free for everybody
- **Wishlist availability + ask to borrow**: `docs/features/wishlist-availability.md` — wishlist cards show marketplace offers (`GetWishlistMarketplaceAvailability`: published, not reserved, not own, blocks hidden, never secret; "Ships to you" = seller's `shipping_countries`) for everybody, plus for the owner which favorites could lend each puzzle (`GetBorrowCandidates` = the one rule: favorites via the `candidate_owners` CTE - widen there only, public system/custom collection, allow list for private owners, no block either way, explicit asker id, lent out shown not askable) + their open asks + "Ask the fewest people" (`BorrowPlanBuilder`, greedy). Marketplace `onMyWishlist` filter + "On your wishlist" label. "Ask to borrow" = selection bar (free players too, Ask only) → sheet modal → `AskToBorrowPuzzles` (one `borrow_request` per owner, `borrow_request_item` per puzzle, idempotent send id, ≤ 10 people / 30 puzzles, limiter `borrow_request` 10/h, skip reasons never tell a block apart) → notification + e-mail (`player.borrow_request_emails`, one-click unsubscribe) → owner answers per puzzle on `borrow_request_detail` (yes / not_owned + optional removal from collection / declined), a yes or "Reply in chat" opens an accepted chat (`StartConversation::$borrowRequestId`); the hand-over stays the members-only lend/borrow forms (pre-filled `?borrower=` / `?owner=`), `CloseBorrowRequestWhenLent` marks the ask `lent`; withdraw, 30-day expiry cron `myspeedpuzzling:expire-borrow-requests`. Asking and answering free for everybody
- **Selecting several puzzles on a collection page (and the other lists)**: `docs/features/collections/bulk-actions.md` — members on their own collection pages tick cards (`collection_selection_controller.js`); the floating bar posts `puzzleIds[]` (body, never the URL; stateless CSRF `collection_selection`) into `modal-frame` for Move to… / Copy to… / Lend to… / Remove (a form outside the modal frame targeting it: `dynamic_modal_controller.js` opens the modal for those too - Turbo fires their fetch events on the form, not the frame). One message per action (`MovePuzzlesToCollection` / `CopyPuzzlesToCollection` / `RemovePuzzlesFromCollection`), two statements for any selection size, answers `SelectedPuzzlesOutcome` (stale ids skipped and counted). Moving keeps the item (`CollectionItem::moveTo()`: id, added date, comment) - the single move too; collections are checked to be the player's own (`CollectionRepository::getOwnedBy()`). The selection lives on the page only. **The other lists** (wishlist: Add to collection… / Remove; sell/swap: Mark as sold/swapped / Reserve / Remove reservation / Remove; unsolved: Add to collection… / Lend to… / Remove from all collections; lend/borrow: Return) share the controller and the bar (`_puzzle_selection_bar.html.twig`, a list of actions), routes `puzzle_list_selected_*` (`Value\PuzzleList` + `PuzzleListSelectionAction`), answers from `PuzzleListSelectionResponder`; existing all-or-nothing batch messages get a `MultiscanEligibility` pre-filter. Gotcha: `SystemMessageSender` flushes - a listing batch tells every conversation before deleting any listing
- **Data export (results + puzzle library)**: `docs/features/data-export.md` — owner-only page `export_puzzler_data` with two downloads in JSON / XLSX / CSV / XML: results (`export_puzzler_data_download`, columns frozen - people script against them) and the whole puzzle library (`export_puzzle_library_download`): flat sections `collections`, `collection_items`, `wishlist`, `lent_out`, `borrowed`, `lend_borrow_history`, `sell_swap`, `sell_swap_events`, `sold_swapped` + `about` (meta + list settings), named the same in every format (CSV = a ZIP with one file per section). Every item row carries the shared puzzle columns (`ExportablePuzzle::SQL_COLUMNS` - one fragment for every export query) plus the player's own solving facts and members-only `difficulty_tier`. One statement per section + two puzzle-level ones, constant in library size (guarded by a query-count test). Own data: private collections and custom collections of a lapsed membership included; counterparties are bilateral history (not blocklist-filtered). **Every spreadsheet cell goes through `SpreadsheetSafeValue`** (text never becomes a formula), responses `Cache-Control: private, no-store`. New columns are fine; renaming/removing one bumps `PuzzleLibraryExportBuilder::FORMAT_VERSION`
