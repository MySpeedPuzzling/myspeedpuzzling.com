# My data: custom fields and the data import

Loaded automatically when you read or edit files of this area (custom fields "My fields", the spreadsheet / Google Sheets import, the My data pages). Read on purpose when planning work here before touching code. Each entry is the as-built summary; its doc under `docs/features/` is the design of record - read it before changing behaviour, and update both when behaviour changes.

Both write results: the rules of `.claude/rules/features/results.md` apply too (a solving time is deleted only through `PuzzleSolvingTimeRepository::delete()`, the add-result form must never break), and custom values stay private (`.claude/rules/queries.md`).

- **Custom fields ("My fields")**: `docs/features/custom-fields.md` — a player's own private fields on their results and on the puzzles of their collections (text, number, date, yes/no, one of a list, free tags, rating 1-5 = radios, no JavaScript; 20 in use, archive keeps the values), ready-made ones with a fixed key (`Value\StandardCustomField`, name in the page language), manage page `my_fields` (`/{_locale}/custom-fields`), values form of a result `result_my_fields` (own route + message `SetSolvingTimeCustomValues`, **never** `EditPuzzleSolvingTime`), owner-only block on the result detail. Stage 1 of the data import (`docs/features/data-import/`), free for everybody. Tables `player_custom_field` (not `custom_field` - Doctrine ignores `custom_*`) and `solving_time_custom_values` (a row per result **and player**: a pair partner has their own); a collection item's values are the column `collection_item.custom_values`. **Collection pages are often public: an item's values are never rendered or selected on a collection page, list, card, API answer, the marketplace or lending - not for the owner either.** They are a *private* property of `CollectionItem` (`customValues()` / `changeCustomValues()` / `fillCustomValueGapsFrom()` - every caller is listed in the coverage test), read by `GetCollectionItemCustomValues` (bound to the viewer), written by `SetCollectionItemCustomValues`, shown only in the item's edit form (`EditCollectionItemCommentController`: the comment form keeps working whatever happens to the fields - read failing open, checked first by `SubmittedValuesChange::problems()` (an invalid value = 422 and nothing saved), then the comment, then the fields by a step that never throws) and in the owner's exports (`OwnCustomValuesInExport` takes no player id; `custom:<key>` for a ready-made field, `custom:own:<name>` for an own one - `data-export.md` "Own fields", 2 statements). **Nothing of a value goes to Sentry:** the SDK attaches the request body to every event, so `OwnFieldsSentryScrubber` (`before_send`, via `SentryBeforeSend`) withholds `my_fields` from it and the arguments of frames inside the fields' code, and `GenericObjectSerializer` never prints the values of the two messages - a new form posting `my_fields[…]` is covered, a new input name or message carrying values is not until added there. A copy starts with the source's values, a move keeps the row, two items of one player becoming one (move into a collection holding the puzzle, puzzle merge) fill the staying item's gaps - never into the merge audit. **Private by construction:** one reader `GetCustomValues::forViewer()` bound to the viewer, never joined into a shared read or the API - `CustomValuesCoverageTest` (every `src/` file naming the storage is listed, every template whose Twig names the values, and no query may read `collection_item` with a wildcard; that is why routes/texts/templates/inputs are `my_fields…`) + `CustomValuesPrivacyCanaryTest` (**add every new surface showing a result, a player, a collection or its puzzles**). **In the add-result form the fields are beside the form, never part of it:** plain `my_fields[<id>]` inputs (no Symfony children - `PuzzleAddFormType`, the add messages and handlers untouched), saved after the result by `AddFormCustomFields::saveSubmitted()` - the controller's **last** step on both paths (the answer is built first), which never throws (a value that can not be stored is left out + named in a flash, never a 422; the warning carries a `CustomValuesWriteFailure`, never a driver message - it can quote the values), loading fails open, for a player without fields only the static "Add your own field" line + an empty `<dialog>` (the line and "Manage my fields" open the manage page's own body there - `Turbo-Frame: my-fields-panel`, `my_fields_panel_controller.js`; the dialog is moved out of the result's form before anything loads, closing it re-fetches the block `my_fields_add_form_block` and keeps what was typed; never `modal-frame`) (one statement, "has none" remembered 2 min in the session - `ViewerResultFields`), kill switch `CUSTOM_FIELDS_IN_ADD_FORM`. The services shared pages call take **no player id** (they resolve the signed-in player). Text = valid UTF-8 without control characters, an ambiguous number (`1,250`) is refused. **A copy of a result removed as a duplicate hands its custom values to the kept result first** (`CustomValuesOfRemovedCopy`, called by `KeepDuplicateCopyHandler` + `AutoRemoveCertainDuplicateHandler`; kept values win, an Undo restores the copy without them)
- **Data import of spreadsheets + My data**: `docs/features/data-import/` (README = design + decisions, `implementation-plan.md` = stages, **`STATUS.md` = the living record**, a doc per part: `upload.md`, `google-sheets.md`, `reading.md`, `columns.md` + `columns-screen.md`, `layouts.md`, `pairing.md` + `pairing-screens.md`, `adding.md` + `adding-screens.md`, `writer.md`, `group-answers.md`, `date-precision.md`, `unlisted-puzzles.md`, `people.md`, `entry-points.md`; **the screens' design of record = `guided-flow.md`**: five steps File / Check / People / Puzzles / Add, "Where you are", one primary button per screen, the vocabulary of its §8) + `docs/features/my-data.md` + `docs/features/custom-fields.md` — free for everybody: a player brings an `.xlsx` / CSV / TSV file or a Google Sheets link (`data_imports` `/{_locale}/import`, owner-only, `noindex`; public guide `import_guide` in all 6 locales, anchors pinned by `ImportGuideControllerTest`), the worker reads it (`imports` transport; safety net `myspeedpuzzling:read-waiting-imports` every 5 min), the columns are recognised (known exports = `KnownExportLayout`: Puzzle Tracker's CSV, our own results export; a confirmed mapping is remembered as a layout), every puzzle is looked up in the catalogue (sure matches by themselves, the others chosen by the player from pictures), and after a review **"Add"** writes results, collection puzzles and wish-list puzzles in batches (`myspeedpuzzling:continue-import-batches` every 5 min). **The add-result form's controllers, messages, handlers and form types are never touched by any of it**: an imported result is written by `ImportedResultWriter` next to them (`created_via = spreadsheet_import`, a partner written as a `#code` is that player - blocks respected, daily limits per partner - and a plain name is asked about and stays a guest unless the player says who it is (`people.md`), no photo, a day or only a month / year - `date-precision.md`), and `ImportWritePathParityTest` saves the same input through the form and through the import and compares what was stored - a change to either path must keep it green. **Never twice** (`ImportNeverTwice`, `ImportNeverTwiceTest`): a row's `source_key`, state and links to what it made are kept for ever, so the same file again adds nothing and new rows are added; the player's typed results are recognised too. **Everything can be taken back**: every "Add" is a batch with an append-only log, Undo per row / batch / import keeps a result the player edited since. Unusual times are asked about before "Add" (one answer for a group - `group-answers.md`), never marked quietly. **The row's editor** (`pairing-screens.md` "The way back", "No time"): every link into it carries `?return=` - taken only when it is one of the import's GET pages a player can come from (the closed list in `Value\DataImport\ImportRowOrigin`, on top of `ReturnUrl` - a new screen linking to the editor is added there) - a save leads back there (else to the next row that needs a look) and the flash names the row; its forms are `data-turbo="false"` so the anchor survives the redirect (buttons locked by `data_import_submit_once_controller.js`); "No time - I didn't time this one" is the time's answer `ImportRowAnswers::NO_TIME` and makes the row exactly what an empty time cell makes it (a result without a time - never a new write path; it never says "solved" by itself: not offered nor taken for a shelf row with an empty time cell). the save's "Row 14 is saved" is its own flash (`SaveImportRowController::SAVED_FLASH`) rendered fixed in view by the flow header (`_saved_notice.html.twig`) because the landing page is scrolled to an anchor. "Rows we could not read" answers in place with Turbo Streams (`_to_fix.stream.html.twig`, `data_import_settle_controller.js` keeps the layout from jumping), the redirect is the no-script fallback; "Import all of them without a time" answers every time group at once; saving a sheet's columns moves on to "Where you are". **The pause switch** (`data_import_settings`, flipped on `/admin/imports`, asked before every row) stops adding without losing anything; Undo is never paused. The file is kept `DataImportLimits::KEEP_FILE_DAYS` (30) days (`myspeedpuzzling:prune-data-imports` daily), ≤ 2,000 results made public per player a day. **Unlisted puzzles** (`unlisted-puzzles.md`: a puzzle of the file that is not in the catalogue, with its results and ownership, on the owner-only `unlisted_puzzles`; `myspeedpuzzling:pair-unlisted-puzzles` daily only suggests, the player pairs; **"Add to the catalogue"** on an unlisted puzzle = `AddUnlistedPuzzleToCatalogueController` dispatching the add form's `AddPuzzle` and then `PairUnlistedPuzzle`, both unchanged - photo required, what would refuse the match is asked before the puzzle is made, the player's own puzzle waiting for approval leads the form so adding again never makes a second one, 10 new puzzles a day, modal on the list with a Turbo Stream; the user menu shows the page only to a player who has some, remembered in the session by `ViewerUnlistedPuzzles`): **the unlisted tables are never part of a shared read** - no public page, list, search, statistic or API - guarded by `UnlistedDataCoverageTest` (**add every new reader there**). **My data** (`my_data`, `/{_locale}/my-data`, owner-only): the player's results and puzzles as a table with their own fields (`custom-fields.md`) as columns - reads through the viewer-bound readers only, never a shared one. Where all of it is linked from, and what is deliberately not: `entry-points.md` - **an entry point is a link, never a statement more on a page**; the add form's page carries one static line outside the form
