# Players, profiles and social features

Loaded automatically when you read or edit files of this area (the player header, Players page, compare, blocklist and private profiles, notifications, the activity feed, onboarding, karma/XP/achievements, hints and modals). Read on purpose when planning work here before touching code. Each entry is the as-built summary; its doc under `docs/features/` is the design of record - read it before changing behaviour, and update both when behaviour changes.

- **Player header**: `docs/features/player-header.md` — every page of one player (24 templates) uses `<twig:PlayerHeader player tab=… />`: avatar (`_player_avatar` size `xl`, the flag is the country) · name (H1 with `:heading="true"`) · `#CODE` · chips (tier rules in `PlayerHeader::tierChip()`: opted out = none, not ranked = "No tier yet" for members, lock for others), Favorite (filled while in your favorites; links carry `?return=`) + Message (`canMessage`, queried only when DMs are off) or own Share (`share_link_controller.js`) + Edit profile, ⋯ with every action (`player/_header_actions_menu.html.twig`, rendered in header **and** bar - no ids), page tabs (`Value\PlayerHeaderTab`; Favorites owner-only), compact bar with the tabs = the puzzle page's `compact_bar_controller.js`/`.compact-bar*`. Owner-only form/history pages pass `:compact="true"` → one-line strip. The Favorites page is personal: owner only (302 to the profile for anyone else), "Who has you in favorites" via `GetFavoritePlayers::followersOf()` (blocked either way = left out, hidden private = only counted)
- **Players page (people discovery)**: `docs/features/players-page/README.md` — `/en/puzzlers` helps a puzzler find people worth following. World by default, one tap to a country (`?scope=cz`, `CommunityScope`; guests get a client-side country guess so guest HTML stays shared-cacheable). Sections = one component each (`src/Component/Players/*`): Spotlight (numbers + Most active / Most followed / New faces, Show more), This week (On a roll + moment chips), Suggested for you (signed in, reasons, blocks both ways), country tiles + Country Cup (per active puzzler, 10+ active), "Add your country" nudge; player card = Turbo Frame `player_card` (members-only activity strip + tier); directory `players_directory` (`/en/puzzlers/all`) also under every country page. **Everything listed is precomputed** every 15 min by `myspeedpuzzling:recalculate-community-stats` into `community_player_stats` / `community_scope_stats` / `player_moment` (personal bests, milestones, first results - stable ids, meant for the future Hub feed); a person-result = solo tracker + every registered pair/team member. Hub = results, Players = people: never list single results here. Person lists are public-only for everybody. Guards: `PlayersPageCanaryTest`, `PlayersPageQueryBudgetTest`
- **Compare (line-ups)**: `docs/features/player-comparison.md` — replaces the old 1:1 `compare_players` page (old URLs 302 to a no-write `?with=` preview). **Persistent** per-player line-ups in `comparison_subject` (player = solo times, `puzzling_team` = exact pair/team), **like with like**: separate Solo · Pairs · Teams line-ups, never mixed. Cap per kind `ComparisonLimits` (members 10 incl. yourself; free Solo = you + 1, Pairs/Teams 2; at the cap free users get a swap). Page `comparison` (`/{_locale}/compare`, Live component `Comparison`, URL is the filter state via `ComparisonCriteria::fromUserInput()` - members-only values (first tries, custom range, brand, difficulty, difficulty sort) stripped server-side); 2 subjects = head-to-head + side-by-side rows, 3+ = league table + Table (default)/Cards views (`player.comparison_view`; the Duel view was removed 2026-10-03), the A/B pair picker only on the Charts tab and next to a lead/lag sort; "Show more" paging belongs to a list (`Comparison::$pagedList`) - never reset paging in a prop's `onUpdated` hook, Live re-sends `<select data-model>` values whose option differs from the prop (`""` vs null) with every request; "Clear" = `ClearComparisonLineUp` (Solo keeps you); members: charts (`ComparisonCharts`) and "Someone at your speed" (`FindSimilarSpeedPuzzler`) - **never call it "rival"**. One aggregate statement for all subjects (`GetComparisonResults`), builder in PHP (`ComparisonBuilder`), query count constant in line-up size. Visibility re-checked on every read; handlers use explicit owner ids (`ComparisonSubjectVisibility`), only the viewer's own blocks hide. The viewer's line-up rides on the profile row (`PlayerProfile::$comparisonLineUp`) → header compare button (icon-only; Favorite becomes a star below 380 px when Message is shown - measured in 6 locales), ⋯ menu, team page button and the floating launcher pill cost 0 queries. Add/remove from other pages = POST + stateless CSRF (`comparison_add`/`comparison_remove`), PRG
- **Player blocklist**: `docs/features/player-blocklist.md` — site-wide "stop seeing this player" (safety feature: the blocked side must never be able to tell). One `user_block` row = *blocker must not see blocked*; `source = self` (profile menu, listed + removable in edit-profile) vs `source = admin` (SQL-only, protects the blocked player, never shown to nor removable by the blocker — runbook in the doc). Read side has no chokepoint: **every `src/Query` statement returning other players' identity embeds `HiddenPlayers::sqlExclude()` / `sqlExcludeTeam()`** (empty string when the viewer blocks nobody → SQL and plans unchanged; filter *inside* ranked subqueries so positions close up; group times survive when the viewer took part). `GetPlayerProfile::byId()` 404s hidden players for all profile pages + `/api/v1/players/{id}`. Guests, cron, async handlers and `/admin` see everyone; async notification handlers check `GetUserBlocks::blockersOf()` instead. Aggregates and bilateral history (lending, sales, ratings) are deliberately unfiltered. Guards: `BlocklistCanaryTest` (add every new player-listing page) + `BlocklistQueryCoverageTest` (allowlist with reasons)
- **Private profile allow list**: `docs/features/private-profile-allow-list.md` — a private player lets chosen players see them (`private_profile_viewer`, owner → viewer, managed at `/en/who-can-see-my-profile`). **`PrivateProfileAccess` is the only code that may unmask a private player**: queries select `sqlIsPrivate('alias')` (or `sqlIsPublic()` in personal lists) instead of raw `is_private`, so `isPrivate` on every result/template/API means *hidden from this viewer* and anything unconverted keeps hiding. Costs no query: ids ride on the viewer's own profile (`revealedPrivatePlayerIds`), API tokens share the blocklist's lookup (`ApiViewerRelations`); bare column = byte-identical SQL for everyone else. Guests/cron/client-credentials reveal nobody; a block in either direction outranks the list; global rankings stay closed to private players for everybody. The public share image follows the player's *own* setting, never the viewer. Guards: `PrivateProfileCanaryTest` (add every new player-listing page), `PrivateProfileQueryCoverageTest` (raw `is_private` needs a listed reason)
- **Player's time zone**: `docs/features/player-timezone.md` — `player.timezone` (IANA, null = unknown; only what `Value\TimezoneIdentifier` lists, browser aliases like `Asia/Calcutta` mapped), private (`GetPlayerProfile::byUserId()` only, never `byId()`/API v1). Detected at sign-up by a hidden field (`timezone_detect_controller.js`: `/register`, `/register/social`; `/welcome` posts it once while empty), `DetectPlayerTimezone` only fills an empty value, no writes on GET; settings field `edit_profile#timezone` (grouped, ICU names, TomSelect, browser zone preselected but saved only on Save); "Complete your profile" panel (`<twig:ProfileCompletion />`, `HintType::ProfileCompletion`) on the own profile after Getting started and the country nudge. The country field next to it (edit profile + `finish_profile`, both asked up front there) is a flag TomSelect (`_country_field.html.twig`, option values = codes) preselecting "We think you're from …" while empty: the time zone's country (`TimezoneIdentifier::countryCodes()`, saved zone else the browser's), else the browser language - no IP geolocation (doc "The country guess"). `tracked_at` is UTC → convert with the player's zone, fall back to the country's main zone, then UTC
- **Getting started (newcomer onboarding)**: `docs/features/getting-started-guide.md` — name asked at registration; `/welcome` = one question + big buttons (native *and* social sign-up land there); slim `finish_profile` page reusing `EditProfileFormType`/`EditProfile`; "Getting started" card on the Hub + the player's own profile = 5 steps **derived from data** (`GetGettingStartedProgress`, nothing stored), newcomers only (14 days), hidden via `HintType::GettingStartedChecklist`, auto-dismissed by `HubController` when complete, `<details>` open until the first puzzle is logged, folded afterwards; public guide `getting_started` in **all 6 locales** (no screenshots, anchors pinned by test, linked from footer/user menu/FAQ). Deliberately no tour/modal — research in the doc
- **Notifications**: `docs/features/notifications.md` — bell dropdown with the newest 8 (`notifications_dropdown_controller.js` loads `<turbo-frame id="notifications-dropdown">` on the first open, the answer marks everything read) + "Show all"; the page shows 30 at a time with "Show more" frames (`?offset=`); `GetNotifications::forPlayer()` picks the page first (`MATERIALIZED` CTE `page`, the hidden-player rule `notHidden()`) and every UNION branch reads `FROM page notification` - never `FROM notification` (a new `target_*` column has no statistics for weeks: #286/#288 scanned all 4.55M rows). Daily `myspeedpuzzling:prune-read-notifications` deletes read `SubscribedPlayerAddedTime` older than 90 days in 50k batches
- **Live activity feed (Hub + Recent activity)**: `docs/features/live-activity-feed.md` — the `RecentActivity` component has **no `data-poll`** (a bare `setInterval`: 91 % of its refreshes came from desktop tabs open for hours). With `autoRefresh` (Hub, `/recent-activity`) `live_refresh_controller.js` sits on its root: re-render every 60 s (±5 s jitter) only while the component is shown, the page visible and somebody interacted in the last 30 min; back on screen = refresh at once if due; failed refresh = 60/120/300 s backoff, never the error modal (also clears the request Live Component leaves stuck after a rejected `fetch`). The status line "Auto-update in 42 seconds ◯" (`_live_refresh_status.html.twig`, rendered by the component as `data-live-ignore` so no morph touches it; on the Hub on the "Show more" row, on `/recent-activity` in the gap above the table) counts down and is the WCAG 2.2.2 pause/resume button (pause/play icon in the ring, a pause is page-wide); its ring fills smoothly through two Web Animations of `transform` only (compositor, never a stroke animation - that repaints every frame; steps under reduced motion). Its texts come from `browser_translation()` = raw message + the locale of the catalogue that defines it, so `assets/translation_choice.js` picks the plural form like PHP's fallback does (English rules on a page not yet translated). "… ago" labels count up everywhere the feed renders (`relative_time_controller.js` + `assets/relative_time.js`, one page-wide timer `page_ticker.js`): `<time datetime data-relative-time>`, raw `time` catalogue strings via `relative_time_messages()`, server clock offset, < 28 days only; **wording parity with Twig `|ago` is pinned by `RelativeTimeParityTest` (node)**. JS writes label text only, never attributes (Live Component re-applies JS-changed attributes after a re-render). Rows carry ids (`activity-{all|favorites|player}-{id}`) so a new row is inserted, and "Show more" is a class on `.ra-list`, kept across refreshes. Mercure deliberately not used: the feed is personal (blocklist, private profiles), see the doc for the competition-scale plan
- **Hint Dismissing**: `docs/features/hint-dismissing.md` — Dismissable hint banners with `dismiss-hint` Stimulus controller, `HintType` enum, per-user persistence
- **Announcement modals**: `docs/features/announcement-modals.md` — modals the site opens by itself, **once per player ever**: `AnnouncementModal` enum + a template per case that stays in the code + one `AnnouncementModalRule` service each (no queries in rules - they run on every page view), picked by `ResolveAnnouncementModal` (full-page GET only, quiet routes, no `?return=`, web only, 14-day pause between modals). **Never twice = the impression is claimed before rendering** (`INSERT .. ON CONFLICT DO NOTHING` into `player_modal_impression`; only the winning request renders); the browser's `seen_at` report is for counting only. `announcement_modal()` claims - `base.html.twig` is its only caller. `player.modal_displayed` is dead and gets dropped one release later (blue-green)
- **Opt-Out Features**: `docs/features/opt-out.md` — Streak and ranking opt-out for players
- **Karma**: `docs/features/karma.md` — 1 karma per accepted contribution to the puzzle database (approved change/merge request, approved puzzle with an EAN - earliest copy of merged duplicates only, each moderator decision and direct edit; own proposal decided = 1 in total), no caps, admins count too (since 2026-10-12), never negative, no XP. Kudos: `KARMA_INFINITE_PLAYER_IDS` (prod env only) shows "∞ karma" golden - display only (`InfiniteKarma`). **Derived, no ledger**: `KarmaDerivation::itemsCte()` is the one rule, `player.karma` its cache (`KarmaRecalculator`, set-based UPDATE; `RecalculateKarma` async from the deciding handlers, `myspeedpuzzling:recalculate-karma` daily). History `karma_history`, explainer `karma_explainer`, list = `xp_leaderboard?tab=karma`, header chip, proposer track record in the review queues. Launches with XP behind `XpFeatureGate`
- **XP / Levels / Achievements**: `docs/features/xp-levels/` — XP ledger + level curve (1–50), tiered achievements with Achievement Points (21 since 2026-10-29), weekly content digest, launch runbook. **New achievements come in monthly drops**: an `AchievementDrops` entry per drop ("New" tag 30 days, digest block, reveal invite in digest + Hub - no modal), released by `recalculate-badges --sync` then `date-achievements-from-history --earned-since` (runbook in docs/features/badges.md "Achievement drops"). No feature flag: the launch switch `xp_settings.launch_ready_at` (set by `myspeedpuzzling:xp-backfill` only after it verified the history) keeps it admin-only until then; achievements grant AP only, never XP; formula cutoff = the deploy moment (`xp_settings.full_formula_from`); the launch reveal is an announcement modal + `/my/xp-reveal`; living doc in `docs/features/xp-levels/README.md`, decisions in `launch-2026-10.md`. UX polish design of record (every decision with its reason): `docs/features/xp-levels/ux-polish/design-spec.md` - achievements shelf (`_achievements_layout`/`_achievement_cell`), the detail sheet (`_achievement_info_modal`, holo medal `holo_medal_controller.js` with masks precomputed by `tools/badge-art`, medal serial `GetAchievementMedal`, tiers still carrying the launch backfill's stamp = "Held at launch", `HeldAtLaunch` = the window deploy..switch; every other tier got the date its requirement was first met from `myspeedpuzzling:date-achievements-from-history`, 2026-10-12, docs/features/badges.md "Real dates"), breadcrumbs + back `_page_crumbs.html.twig`, every leaderboard's "where am I" `Value\LeaderboardWindow::board()`
- **Player code history**: `player_code_change` (previous/new code, when) - written by `EditPlayerCodeHandler` on every real change, cascades with the player. A log only, nothing reads it yet; a personal code is a member feature a free trial hands out too
- **Feedback screenshots**: `docs/features/feedback-screenshots.md` — up to 3 pictures in "Send feedback" (pick, paste, drop), uploaded in the background into the player's `PhotoStash` like the add-time form's photos; `CollectUserFeedbackHandler` re-encodes each (`ImageOptimizer::toJpeg()`, 2000 px - no EXIF/GPS, decoding = the type check) and attaches the bytes inline to the e-mail - nothing stored, no links; an unreadable picture is left out with a note, the message always goes; rate limit `feedback` 10/h per player
- **Feature request e-mails**: `docs/features/feature-requests.md` — completed/declined → author, upvoters and players following every request (`player.feature_request_emails`: `upvoted` default / `all` / `none` = not even own requests), one-click unsubscribe on each; `feature_request.completed_at` + sort "Recently completed"
- **Site footer**: `docs/features/site-footer.md` — dark `$gray-900` footer, the same columns for everyone (Discover / Track / Learn / MySpeedPuzzling, no "New" badges since 2026-11-11, straight top edge — Jan's calls 2026-10-02); guests also get the newsletter band + grouped "Popular searches" (`<details>`, open from md up via `::details-content`); players only get a quiet "Turn it on" line when the newsletter is off (unticked box at registration since 2026-10-12, earlier players count as opted in); `_language_menu.html.twig` shared with the topbar
