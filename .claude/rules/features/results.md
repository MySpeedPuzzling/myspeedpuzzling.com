# Results and solving times

Loaded automatically when you read or edit files of this area (adding/editing results, pairs and teams, first tries, duplicates, time verification, photo uploads, the result detail, and leaderboards; custom fields and the data import: `my-data.md`). Read on purpose when planning work here before touching code. Each entry is the as-built summary; its doc under `docs/features/` is the design of record - read it before changing behaviour, and update both when behaviour changes.

- **Editing pair/team times**: `docs/features/group-time-editing.md` — every registered group member may edit a group time, only the tracker may delete (`PuzzleSolvingTime::canBeModifiedBy()`, read side `isEditableBy()`); the group is always assembled around the tracker, never the editor; other members get a `GroupSolvingTimeEdited` notification naming the editor (`notification.actor_player_id`)
- **Result detail**: `docs/features/puzzle-result-detail.md` — route `puzzle_result_detail` (`/en/result/{timeId}`, all 6 locales): one player's - or one exact pair's/team's (`puzzling_team_id`) - results on one puzzle, subject derived from the time, never the URL; modal on `Turbo-Frame: modal-frame` (else full `noindex` page, canonical = puzzle, `Vary: Turbo-Frame`); `GetPuzzleResultDetail` = 2 statements (attempts + one aggregate standing that must equal the leaderboard row, guarded by a parity test); 404 for hidden players / private subjects, suspicious times listed (badge) for everybody else, never the best attempt nor in the standing; og:image = the puzzle photo; links inside the modal need `data-turbo-frame="_top"` (`links_turbo_frame` var read by `_leaderboard_player`/`_competition_badge`); chart members-only
- **Puzzle leaderboard chart + "where am I"**: `docs/features/puzzle-leaderboard-chart.md` — table renders the top 100 rows (`PuzzleTimes::DEFAULT_LIMIT`, "Show more"/"Show all" Live actions) plus the viewer's row with ±2 neighbours after a "⋯" row; position line "#X of Y · top N %" (rank share, `Value\RankShare` + `_rank_share.html.twig` - also on the profile results chip, the result detail and the recap; rounded up, one decimal, two under 1 %, nothing below 10 on the list) + the gap to the next milestone rank for every signed-in player; members' chart from 20 filtered rows (`PuzzleTimesChart::SWITCH_MIN_ROWS`) = the time distribution by default (`LeaderboardHistogramBuilder`: nice bar widths, at most `maxBins(rows)` = min(30, max(5, 2⌈√rows⌉)) bars, outliers beyond 3 IQR folded into open end bars) or the ranking (a bar per row) through an icon-only switch lying on the chart's top right corner (Symfony UX Icons in `assets/icons/`, `view_icons` in the template), below 20 rows always the ranking without a switch; the choice is remembered on `player.leaderboard_chart_view` (read on the viewer's own profile row - no query of its own; `PuzzleTimes::changeChartView()` Live action); the chart's container is keyed by view (`#leaderboard-chart-{view}`) so a switch rebuilds the chart instead of morphing one into the other; median/"You" markers on both views drawn by `leaderboard_chart_controller.js`; always built from the whole filtered list, never from the visible rows; the "⋯ N more" gap row reveals all the rows it counts (`revealGap`), "Show more" under the table continues after the last row shown - after the viewer's rows while they stand apart (`$belowOwnRow`); the revealed rows belong to a list (`PuzzleTimes::$pagedList` = tab + filters) - never reset them in a prop's `onUpdated` hook (Live re-sends the country select with every request; see the Hotwire guide's Gotchas)
- **Pairs & teams**: `docs/features/pairs-and-teams/README.md` + `implementation-plan.md` — every pair/team result belongs to a `puzzling_team`: **the exact set of people** (order irrelevant, no rosters; identity = `composition_key`, the only implementation is `Value\TeamComposition`; guests keyed by normalised name). `puzzle_solving_time.puzzling_team_id` is **always set together with the `team` JSON snapshot** (constructor / `modify()`); the JSON stays the display snapshot, so old read queries are untouched and select the column as `team_id`. `PuzzlingTeamResolver` = lookup + one-statement `INSERT … ON CONFLICT DO NOTHING` outside the unit of work (race-safe; call it *after* every validation of the handler). A team never changes members — editing a time's group moves the time; `DeletePlayerHandler` turns the member into a guest in place (`PuzzlingTeamMemberConversion`, merges on key collision; the member FK is RESTRICT on purpose). Name = optional, shared, public, ≤ 50 chars, any *registered* member renames (`RenamePuzzlingTeam`, others get `PuzzlingTeamRenamed` notification), the add form may only name an unnamed team (`team_name` field → `nameIfUnnamed`). **A team with results can never be deleted** (`DeletePuzzlingTeam` → 409). Add-form picker: `_copuzzler_picker.html.twig` + `copuzzler_picker_controller.js` — hidden `group_players[]` inputs are the single source of truth (wire format unchanged), per-mode stash so switching Solo/Pair/Team never loses anything, nothing in it may submit/re-render/navigate (Enter in the search included) - except that it stops a submit while typed text was not added or Pair/Team holds nobody; **one input = one person, commas split** (`PuzzlersGrouping::splitInputs()`, mirrored in the picker; old combined guests: `myspeedpuzzling:split-combined-guests`), suggestions fetched lazily from `/{_locale}/my-co-puzzlers.json` so **a solo form pays no query**; kill switch `PAIRS_TEAMS_PICKER_PUBLIC` (1 = public; 0 = old co-puzzler rows for everybody but admins). Pages: `/{_locale}/pairs-and-teams` (manage), `/{_locale}/teams/{id}` (public, stats members-only, `noindex` when unnamed), profile "with…" filter + puzzle page "My pairs/teams only" (both filter in PHP, zero queries). One-off backfill: `myspeedpuzzling:backfill-puzzling-teams` (keyset batches, idempotent). **Guests** (Guests tab of the manage page): `PuzzlingTeamMemberConversion` is the only code that changes who a member is — `playerToGuest` (deletion), `renameGuest`, `guestToPlayer`; it merges on key collision and rewrites the group snapshots; a guest becomes a player **only with that player's consent** (`GuestLinkRequest` → notification → `/pairs-and-teams/guest-link/{id}`, GET only shows, answer is a POST; a player who blocks the asker is never asked and the asker cannot tell). **Archive** = one member's own "keep out of my shortcuts" (`puzzling_team_archive`), touches nothing else, undone automatically inside the resolver's lookup when the same people puzzle again. `myspeedpuzzling:cleanup-empty-puzzling-teams` (manual) removes empty unnamed leftovers. API result rows carry `team_id` + `team_name` (additive; never rename API fields, `solo`/`duo`/`team` stay). Team routes require a UUID so `/pairs-and-teams/guests/...` is not read as a team id. **Boot migrations run under a Postgres advisory lock** (`bin/migrate-database`, `MigrationLock`, fails open) — two blue-green containers take turns
- **First-try integrity**: `docs/features/first-try-integrity.md` — one first try per registered person per puzzle across solo + every pair/team result they are in (guests ignored); a pair/team result is a first try only if it is everybody's. **Hard block** when anybody of the result already holds a first try (move it here only if the player is on every held result, never touching a teammate's own result), **warning** for an earlier-day solve without the tag, **tolerated** on an edit that neither newly ticks nor adds anybody. One read model `GetFirstTryTimes` + one decision `FirstTryAssessor` for the forms (checked *before any dispatch* — a refused first try must not leave a new puzzle behind), the live check `GET /{_locale}/first-try-check` (same `_notice.html.twig` as the 422), the handlers (authoritative, `FirstTryAlreadyTaken`) and API v1 (422 via `FirstTryConflictResponse`). People hidden from the player (private without them on the allow list, or blocked) are **left out completely** — no block, no warning, no line; the duplicate lands on *their* conflicts page. Conflicts are resolved (`ResolveFirstTryConflict`) and late first tries reviewed (`first_try_review_dismissal`) on "Review your results" `review_results` (see Duplicate results; old `/first-try-conflicts` = 301). **Every refused add/edit submit keeps its photos** (`PhotoStash`/`FormPhotoStash`: `tmp-uploads/<playerId>/<token>` + JPEG preview, restored into the request before `handleRequest()`, daily `myspeedpuzzling:prune-photo-stash`)
- **Photo uploads on slow connections**: `docs/features/photo-uploads/README.md` — the add/edit-time form and multiscan quick-add upload each photo **in the background the moment it is picked**, shrunk (2000 px / JPEG 0.85 - Jan: never smaller), **straight to object storage** by presigned `PUT` (`PhotoUploadStartController` `POST /{_locale}/photo-upload` → `DirectPhotoUpload`, signed type + exact length, the online competitions' `S3QueryPresigner` + bucket CORS) into the PhotoStash (`tmp-uploads/<player>/<token>`; the description that makes a token work is a `photo_stash_entry` row written through messages - the start makes **no** object-storage call, evicted/replaced objects go with the daily prune); Save sends only `photo_stash[<field>]` tokens. Why: a slow multipart upload holds a FrankenPHP worker for its whole duration (measured) and Traefik cut it at 60 s (incident 2026-10-14). `assets/photo_upload.js`: progress line per photo, stall watchdog 30 s, backoff retries + `online` event, anything that cannot work (refused, store 4xx, instantly unreachable) **goes with the form as a file** - the plain form is the floor. **A photo the phone cannot read never blocks a save** (README §4.2, incident 2026-11-14: a 0-byte photo made every Save die in the browser): `assets/photo_readability.js` - 0 bytes or a refused one-byte read = taken out of the form with a note (on pick, on the start's `empty` refusal, right before the request; a check that cannot tell = readable), a save lost at once with a photo in the request says both (connection or photo: "Try again" + "Save without the photo"; the photo is named only the second time in a row; a new puzzle's box photo is never taken out), a photo taken out while saving travels as `photo_dropped[<field>]` so the next page's flash says it, and `EmptyPhotoParts` makes a 0-byte photo part count as no photo on the server. Save waits for uploads (progress on the button); a lost save **without** photo bytes is resent once by itself (idempotent ids). **The add/edit-time form no longer deletes its kept photos on save** (a resend must restore them → answered as the saved result); they expire after 24 h, 20 per player. Telemetry `/-/photo-upload-report` → channel `photo_upload` (info; warning only for the store refusing a signed upload). Kill switch `DIRECT_PHOTO_UPLOADS`
- **Duplicate results ("saved twice")**: `docs/features/duplicate-results.md` — **a save happens once**: the add form carries hidden `time_id` / `new_puzzle_id` (UUIDv7, kept on a 422 - every add form must keep them), so a resent form answers the saved result (`SolvingTimeAlreadySaved`), plus a ≤ 10 s identical-copy safety net in the handler. The form check (same time already saved: confirm on the same day via `duplicate_confirmed`, a line for another day) comes from `FirstTryAssessor::check()`'s one query. **Cases** per person (`result_duplicate_case`, tiers A/B/C) from save-time detection + daily `myspeedpuzzling:detect-duplicate-results`; Tier A is removed automatically (`result_auto_removal` snapshot, Undo restores the same id). Players decide on `review_results` (`/{_locale}/review-results`; cases sharing a result = one set of copies: keep one / all real, only a copy's tracker deletes it) + banner on Hub/own profile; weekly "Your results" e-mail (own switch `player.result_emails_enabled`, planned daily + sent every 5 minutes around the clock, spaced one a minute via `DelayStamp` (`DelayedEmailQueue`; `RESULT_REVIEW_EMAILS_PER_RUN` 5 / `RESULT_REVIEW_EMAIL_SPACING_SECONDS` 60 / `RESULT_REVIEW_EMAILS_PER_DAY` 1000 = guard), `notifications` transport, preview `myspeedpuzzling:send-result-review-email-preview <email>`, signed one-click unsubscribe). Admin `/admin/duplicate-results` (incl. duplicate puzzle signals → "Propose merge"). Edit can move a result to another puzzle (tracker only)
- **Suspicious times**: `docs/features/suspicious-times.md` — `puzzle_solving_time.suspicious` (set in the time verification queue, or by SQL - the next scan reconciles it) is **neither counted nor timed anywhere** (leaderboards, ranks, "Completed N×"/`puzzle_statistics`, medians, profile stats/charts/calendar, totals, Players page, insights, shared feeds) - the player's own solved status, first tries, duplicates and admin tools still see it; shown, with the "Verification needed" badge from `_leaderboard_time_badges.html.twig`, only in somebody's own results (profile + its feed, pair/team page, the result detail opened from them). Guard: `SuspiciousTimeQueryCoverageTest` (code reading `puzzle_solving_time` must mention suspicious or be listed with a reason)
- **Time verification (suspicious time review)**: `docs/features/suspicious-time-review.md` — **the scan never marks**: `myspeedpuzzling:detect-suspicious-times` (cron 04:19 + 16:19, `--dry-run` before a `SuspiciousTimeClassifier::VERSION` bump) checks every time against **the player's own times** (stored prediction → baseline × difficulty → pace on their other solo results; the community scale only for a player without times of their own; a prediction built on a far too slow attempt is not trusted), **fast and slow** (pair/team only by the community's slow floor), opens cases with reasons + explanations (hours left out, a group saved as solo, another edition - never a secret/hidden puzzle, minutes in the hours box, days counted) and reconciles flags set by SQL; a check is final per version and entry fingerprint, a person's decision binds to the entry. Moderators decide at `/admin/time-verification` (`REVIEW_SUSPICIOUS_TIMES`, English only, private players' times only while queued; puzzle cards = ≥ 2 players and a fifth of the puzzle's results, or difficulty < 0.5 / > 2.0 - every case decided right in the card; a hard puzzle (all one colour) gets the moderators' own **slow threshold** on its card, `SetPuzzleSlowThreshold` → `suspicious_time_puzzle_confirmation.slow_threshold` for the current piece count: every slow rule needs max(rule, N)×, fast rules untouched, the puzzle's times judged again at once via `DetectSuspiciousTimes(onlyPuzzleId)`). **A mark is told once** per person per mark (notice run after each scan): banner + "Review your results" `#awaiting-verification` + the "Your results" e-mail - `via = run` only, no bell; the player fixes it (an edit of the time, puzzle or people always removes the label - the scan judges the changed result again), says it's correct, or leaves it. The add/edit form asks while typing (`pace_confirmed`, 422 until answered, no edition lookup, fails open). **Never "suspicious" in anything a person reads** - "Needs verification" / "Awaiting verification". Go-live: run once with `--existing-marks-told-by-hand` (the marks existing then were e-mailed by hand), then the cron
- **What an uploaded picture's file carried**: `docs/features/upload-image-metadata.md` — `ImageOptimizer::optimize()` returns a privacy-safe summary read before the strip (`UploadedImageSummariser` → `UploadedImageMetadata`: camera EXIF yes/no, `DateTimeOriginal` + offset as found, Software family, brand only, orientation, original size/format/bytes; **never** GPS, serials, owner/artist/copyright/comment, maker notes, thumbnail, model), stored as jsonb on the owning row (`puzzle.image_upload_metadata`, `puzzle_change_request.proposed_image_upload_metadata`, `puzzle_solving_time.finished_puzzle_photo_upload_metadata`) so it goes with the picture and its owner; changes only with the path (`Puzzle::useImage()`/`takeImageOf()`, `PuzzleSolvingTime::modify()`/`takeOverFrom()`, dropped on `transferOwnership()`); internal API work list `uploadMetadata`, nothing in the UI. Avatars/logos/page pictures strip without a summary on purpose. The add/edit-time form and multiscan shrink photos > 500 KB in the browser (the canvas drops EXIF), so the browser reads the same allow-list first (`assets/photo_metadata.js`, JPEG + HEIC/AVIF, never throws) and sends it with the upload start / `photo_metadata[<field>]` / multiscan's `photoMetadata`; `BrowserImageSummary` checks it strictly and it is stored (`source: browser`) only when the file that arrived has no EXIF (`UploadedImageMetadata::preferring()`)
- **Placing sorts on the profile results**: `docs/features/profile-results-placing.md` — solo tab: sort by rank / top % (free), placing chips `Value\PlacingFilter` + median line `PlacingSummary` (free), "ahead / behind prediction" by the latest attempt (members, not on a profile with predictions off). Every rank = one statement `GetRanking::allForPlayer()` (per-puzzle LATERAL over `custom_pst_solo_board` keyed `(puzzle_id, player_id)`), loaded only for a placing sort/chip, cached 2 min by `allForPlayerCached()` (viewer pool + own-results fingerprint). Nothing precomputed - the doc says why
- **Deleting a solving time** (any path: the player, account deletion, duplicates, the data import's undo, the API): only through `PuzzleSolvingTimeRepository::delete($time, $via)` - it buries the time in `solving_time_graveyard` and writes a `solving_time_tombstone` per registered member (`docs/features/api/solving-time-sync.md`); `SolvingTimeDeletionCoverageTest` guards it
- **Unfinished results (display, step 2)**: `docs/features/competitions-management/unfinished-results-plan.md` (status step 2) — an unfinished result (`pieces_placed` set, no time) is shown with `_unfinished_result_badge.html.twig` ("479 / 500 pcs", "finished in …") wherever a list would show a time - **never as relax** (`SolvedPuzzle::isRelax()`, `RecentActivityItem::isRelaxMode()`), never called a solve (notifications "competed with puzzle", digest "N pieces"); a new results reader selects `pieces_placed` + `finished_later_seconds` or its row silently reads as relax. Puzzle page: `GetPuzzleSolvers::unfinishedByPuzzleId()` (loaded only when `untimedCountsByPuzzleId()` counts one - no statement more otherwise) → `UnfinishedPuzzleResult` (own type, never in the ranked `$times`) → `UnfinishedResultsBoard` (one row per player / exact pair-team **without a ranked row**, most pieces first, the page filters) rendered after every ranked row once none is left below, rank "–"; "My attempts" merges them as `kind: unfinished`. Tests add rows through `tests/UnfinishedResultSeeding.php`, never global fixtures. API/export: `pieces_placed`, `finished_later_seconds` (additive)
- **Unfinished results (write path, step 3)**: same doc (status step 3) — **one rule** `Value\UnfinishedResult::fromInput()` (a round with `minutes_limit` resolved for competition + puzzle + solo/pair/team, `1 ≤ pieces < puzzle's pieces`, a total > limit; `seconds_spent` = total ?? limit) for every writer; event + round settled first by `UnfinishedResultRound` on `SolvingTimeRoundResolver::resolveFor()` / `SeriesEditionResolver::resolveFor()` (a series pick only by its puzzle; where the finished path drops a link, the unfinished one refuses). **Beside the finished path:** `AddUnfinishedPuzzleSolvingTime` / `EditUnfinishedPuzzleSolvingTime` (+ handlers, `UnfinishedWritePathParityTest`); unfinished → finished/relax only via `EditPuzzleSolvingTime(endsUnfinishedResult: true)` - **without it `EditPuzzleSolvingTimeHandler` refuses an unfinished result** (`UnfinishedResultNeedsItsOwnEdit`), so a new edit surface must route an unfinished result (`isUnfinished()`) to its own edit or refuse. Until step 4: the edit page shows "coming soon" (POST 422), API `PUT` 422, My data saves through the unfinished edit
