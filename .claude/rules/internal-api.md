# Internal admin API

## Internal Admin API
- **Purpose:** admin-only HTTP API for triggering privileged ops (initially feature-request status transitions) from outside the shell — primary consumer is Claude Code automating ops, curl as fallback.
- **Base path:** `/internal-api/*` — completely separate from the public `/api/v1/*` OAuth2 API, intentionally NOT in Swagger at `/api/docs`.
- **Auth:** single static bearer token via `INTERNAL_API_TOKEN` env var. Header: `Authorization: Bearer $INTERNAL_API_TOKEN`. Closed-by-default — empty env var disables the API entirely.
- **Firewall:** dedicated `internal_api` firewall + `InternalApiAuthenticator`, `ROLE_INTERNAL_API`. No user accounts, no DB tokens.
- **Extensibility:** auth/firewall/access_control cover the whole prefix. New endpoints are pure controller-drops under `src/Controller/InternalApi/` that dispatch a Messenger message and return `204` (or the changed resource as JSON); path ids use `FirstTryConflictsController::ID_REQUIREMENT`. No security config changes needed per endpoint.
- **Current endpoints:** `POST /internal-api/feature-requests/{id}/mark-{in-progress,completed,declined}` with optional `{"githubUrl": "...", "adminComment": "..."}` body; `GET /internal-api/puzzle-merge-requests` (review queue, incl. fetchable `imageUrl` per candidate) + `POST /internal-api/puzzle-merge-requests` (file a report, `201` + id) + `POST /internal-api/puzzle-merge-requests/{id}/{approve,reject}`; `POST /internal-api/puzzle-change-requests` (file a proposal, `201` + id; skill `puzzle-change-proposal` - catalogue corrections go through review, not SQL; also a base64 `image` and the image pipeline's `source`/`tags`/`confidence`/`modelVersion`/`sourceImageFingerprint` - once per picture and tag, ever: `409 already_proposed`) + `GET /internal-api/puzzle-change-requests` (list: `source`/`tag`/`status`, keyset, decision + picture URLs) + `POST /internal-api/puzzle-change-requests/{id}/{approve,reject}` (`decisionNote` ≤ 500; approving an `image_pipeline` picture copies the original to `originals/<puzzleId>/<fingerprint>.<ext>` first, `409 original_not_archived` if that fails); `POST /internal-api/manufacturers/{id}/merge` (fold duplicate brands in) + `POST /internal-api/manufacturers/{id}/approve` + `POST /internal-api/manufacturers/{id}/delete` (empty brands only, 409 otherwise); competitions/events: `GET|POST /internal-api/competitions`, `GET /internal-api/competitions/{idOrSlug}`, `PATCH /internal-api/competitions/{id}` (keeps the slug on rename), `DELETE /internal-api/competitions/{id}` (only without results, 409 otherwise), `POST …/{id}/approve`, `POST …/{id}/duplicate` (a draft copy), `PUT …/{id}/puzzles`, `POST …/{id}/rounds`, `PATCH|DELETE /internal-api/rounds/{id}`, `PUT /internal-api/rounds/{id}/puzzles`, `GET|POST /internal-api/puzzles`; organizations, series and drafts (`internal-api.md` §"Organizations, series and drafts"): `GET|POST /internal-api/organizations` (created approved), `GET /internal-api/organizations/{idOrSlug}`, `PATCH|DELETE /internal-api/organizations/{id}` (delete only when empty, 409 otherwise), `POST …/{id}/approve` (+ its pending series and events), `POST /internal-api/organizations/{id}/maintainers` + `DELETE …/maintainers/{playerId}`, `GET|POST /internal-api/series`, `GET /internal-api/series/{idOrSlug}` (with its editions), `PATCH /internal-api/series/{id}`, `POST …/series/{id}/editions`, `PUT /internal-api/{series,competitions}/{id}/organization`, `POST /internal-api/{organizations,series,competitions}/{id}/{publish,unpublish}` (unpublish 409 while joined / results / linked times), `POST /internal-api/competitions/{id}/move` (an edition to another series), `POST /internal-api/rounds/{id}/move`, `POST /internal-api/series/{id}/create-organization`; competition create/`PATCH` take `organizationId`, `eligibility`, `draft` (`status` stays the approval state, an approved draft is `approved` + `draft: true`); e-mail blocks and messages to players (`internal-api.md` §"E-mail blocks and messages to players"): `GET|PUT|DELETE /internal-api/players/{id}/email-block` (`PUT` `{"reason"}` = `email_suppression` `source = manual`: nothing at all is sent to the address, sign-in links included, the player reads the reason in a stripe; kept on the address, so changing it frees them), `POST /internal-api/players/{id}/messages` `{"text"}` (chat message from the reviewer player, accepted conversation, answerable); time verification by solving time id: `GET /internal-api/solving-times/{id}/verification`, `POST …/{id}/mark-suspicious` (`note` the player reads, `reasonCodes`, `toldByHand` = we e-mail them ourselves, the app never repeats it) + `POST …/{id}/unmark-suspicious` (= "Looks fine": unmark or trust) - for unmarking after a player's e-mail answer, never SQL; pairs/teams: `POST /internal-api/solving-times/{id}/members/{playerId}/replace-with-guest` (a player added to somebody's pair/team result by mistake becomes a guest - `guestName`, default their name - in that one result only; 409 for the tracker or a non-member); puzzle image analysis (`internal-api.md` §"Puzzle image analysis" - a pipeline on Jan's Mac pushes results daily): `GET /internal-api/puzzle-images?analyzer=&version=&status=missing|stale|all&limit=&after=` (keyset work list, full-size `imageUrl` + `imageFingerprint` = 16 hex of md5(`puzzle.image`) - a new picture always gets a new path, so nothing is stored on the puzzle), `PUT /internal-api/puzzles/{id}/image-analysis/{analyzer}` + `POST /internal-api/puzzle-image-analyses` (≤ 200 items, one transaction, outcome per item) into `puzzle_image_analysis` (one current row per puzzle and `ImageAnalyzer`, generic jsonb `result`, versioned; 409 = picture changed, 422 = invalid), `GET /internal-api/puzzles/{id}/image-analysis`; several Macs in parallel claim images (`POST /internal-api/puzzle-image-claims` = lease in `puzzle_image_analysis_claim`, fresh work before own claims, serialized by the analysis lock + a race-safe statement as backstop, storing a result deletes the claim; `…/release`), and read results back in bulk (`GET /internal-api/puzzle-image-analyses?analyzer=&after=&onlyCurrent=1`); hidden images (`hide_until`/`hide_image_until`) are never listed or accepted; read side `GetPuzzleImageAnalyses::forPuzzles()`; players' finished-puzzle photos (`internal-api.md` §"Finished-puzzle photos", analyzer `finished_photo`, table `finished_photo_analysis` - never in `puzzle_image_analysis`): `GET /internal-api/finished-photos` (work list, a photo only by puzzle + `photoFingerprint` - never a player, a solving time or the stored path; private players' photos never leave the app), `GET /internal-api/puzzles/{id}/finished-photos/{photoFingerprint}` (the image proxy's 1200 px rendition, metadata stripped, streamed through the app), `POST|GET /internal-api/finished-photo-analyses`, daily prune `myspeedpuzzling:prune-finished-photo-analyses`; puzzle picture tags (`docs/features/insights/tags.md`): `GET /internal-api/puzzles/{id}/tags` + `PUT|DELETE /internal-api/puzzles/{id}/tag-corrections/{tagKey}` (admin/moderator word on one tag, survives re-runs, credited to the reviewer player; `puzzle_tag` is written by the daily `myspeedpuzzling:refresh-puzzle-tags` from the `tags` analysis of the current picture ± corrections); picture-based difficulty (`internal-api.md` §"Puzzle difficulty labels and estimates"): `GET /internal-api/puzzle-difficulty-labels` (as-of training labels, aggregates only, secret puzzles never), `PUT /internal-api/puzzle-difficulty-estimates` (≤ 500, outcome per item, current value per puzzle in `puzzle_difficulty_estimate`), `POST|GET /internal-api/puzzle-difficulty-estimates/model` (model runs + evaluation, current = latest), read side `GetPuzzleDifficultyEstimates::forPuzzles()` (current picture only).
- **Moderation endpoints need a reviewer:** the API has no logged-in user, so `INTERNAL_API_REVIEWER_PLAYER_ID` names the player credited with the decision. Empty = those endpoints 400 and dispatch nothing (the feature-request ones don't need it).
- **Puzzle merges are destructive and audited:** web UI and API alike - the full rule is in `.claude/rules/features/catalogue.md` ("Puzzle merges are destructive and audited").
