## 1. Purpose and how to use

- **One implementation subagent per item** (or per item group named in §2). Its brief = the item's section in §4 + the requirement text (Done when / Verify) + the README sections the item cites + the cross-cutting rules of §3 + the item's rows in the ownership table (§5) + the item's rows in the test table (§6).
- The subagent **never commits and never edits `state.md`**. It returns: files changed, tests added/changed, commands run with their last output lines, a translation fragment (§3.6), a registry snippet when it adds destinations (§3.9), doc notes for DOC-01, open issues.
- The **orchestrator verifies** (runs the Verify itself), commits, and records evidence. Items whose Verify names something built later are set to `implemented (verify-after: …)` exactly as listed here and in `requirements.md`; they are re-run in the phase of the last named ID.
- Paths, routes, class names, Twig functions, data attributes and localStorage/sessionStorage keys named here are **contracts** between items: an agent may add private helpers but must not rename them.
- Every item's section lists: files, approach, data/migrations, tests (new + existing changed), budget impact, translation keys, risks, dependencies.

## 3. Cross-cutting rules (paste into every brief)

### 3.1 CLAUDE.md digest
- Single-action controllers (`__invoke`). State changes only through Messenger handlers; controllers/commands dispatch. Repositories never `flush()`. Handlers validate everything **before** mutating (the transaction middleware does not clear the EM on rollback). No DQL/native UPDATE in handlers except a commented bulk case. `ClockInterface`, never `new DateTimeImmutable()`. `Uuid::uuid7()` for ids.
- Services holding per-request state implement `ResetInterface` (FrankenPHP worker mode; the delivery server is `php -S`, so leaks cannot show — `NavigationServicesResetTest` reflects over `src/Navigation/`, `src/Twig/Navigation*` **and an explicit `EXTRA_CLASSES` list** to which every item appends each class it creates or gives a memo outside those paths: `src/Twig/AdminQueueCountsTwigExtension.php` (MENU-01), `InboxTwigExtension`, `HelpTwigExtension`, `AddEntryTwigExtension`, `src/Services/PlayerResults/PlayerResultsBuilder.php`, `src/Services/Community/CommunityPreview.php`, `src/Services/PlayerActionsResolver.php`; prefer keeping memos inside `src/Navigation/` (F21)).
- Migrations: generated with `doctrine:migrations:diff` against a scratch DB built from committed migrations; additive, nullable/defaulted; read line by line. Custom indexes (`custom_*`) hand-written, mirrored in `tests/bootstrap.php` `createCustomIndexes()`, registered in `docs/database-indexes.md`.
- Turbo: forms inside `modal-frame` set an explicit `action:`; stream answers gated on the `Turbo-Frame: modal-frame` header; full-page form POSTs never answer 200 (redirect or 422 with the `FormInterface`).
- Exceptions logged with `'exception' => $e`; `json_ld` filter for JSON-LD; `ReturnUrl::tryFrom()` / `safe_return_url()` at every use of a return URL.
- No route removed or renamed; new routes have paths in 6 locales (JSON endpoints use `/{_locale}/…`).
- Never write migrations by hand except custom indexes; never run migrations on the dev DB.

### 3.2 Chrome selector rule (≈ 85 tests read the first `h1`, `.alert-*`, `.card-body`, `.nav-tabs`, the first/last `form`)
Chrome markup (header, `nav_chrome` block, Menu, shells, footer additions) contains: no `<h1>`; no `<form>` before `<main>` and none after the footer (search is a bare input, Log out a link, language links); no `.alert*`, `.card-body`, `.nav-tabs`, `.nav-pills`, `.nav-link`; `.dropdown-menu` only in the avatar ▾ (never `.more-menu`); own class prefixes (`site-header`, `nav-*`, `bottom-nav`, `menu-*`, `mr*`, never `topbar*`); no `?brand=`/`?tag=`/`?pieces=` links. Menu group headings are `<p class="menu-group-title" role="heading" aria-level="2">` (README allows plain text; ten tests filter `h2`).

### 3.3 `data-nav`
Every `<a>`/`<button>` in a navigation partial carries `data-nav="<surface>/<place>/<item>"` matching `^[a-z_]+/[a-z_]+/[a-z0-9_]+$`. Surfaces: `topbar`, `tabbar`, `rail`, `menu`, `account`, `help`, `footer`, `chips`, `community`, `inbox`, `card`, `page` (end-of-page line); place = `home|puzzles|add|community|profile|none` or the Menu group id. `<html>` never carries `data-nav` (the layout flag is `data-nav-layout`). Each new container is added to `NavInstrumentationMarkupTest`.

### 3.4 Layer checklist (Menu panel, desktop overlay, search view, card, dynamic modal incl. Help and achievement sheets, Results as history owner)
1. History only through `assets/layer_history.js` (GEST-01): `open(id, {element, onClose})`, `requestClose(id)` for ×/Esc/scrim/swipe, `bindDialog(dialog, id)` for `showModal()` dialogs, `visitFromLayer(url)` for programmatic visits, `closeForCache()` in `turbo:before-cache`. Never `history.pushState`/`Turbo.session.history` directly (guard: `TurboHistoryOwnershipTest`).
2. Rule (d) covers every layer: any Turbo visit started while a layer holds the entry is a replace visit; `data-turbo="false"`/external links use `location.replace()`.
3. Closed state is `display: none` (never only transparent); z-index from the F-03 scale.
4. Phones: Menu panel and card use `show()`, never `showModal()` (the bottom bar must stay usable; Bootstrap modals must render above them). `showModal()` only for the desktop overlay and GEST-13's confirm dialog.
5. Opening another layer is a swap (`replaceState`), never `back()` + `pushState()`.
6. Pull-to-refresh does not arm while `layers.isOpen()`.
7. Native app: no entry pushed, close without `history.back()`; JS-opened layers return early and let the `<a href>` navigate.
8. Each layer item re-runs the GEST-01 layer checks (+ GEST-02 for sheets) with the probe (requirements Conventions) for its own layer.

### 3.5 Native-ready checklist (NAV-14; paste into every bar/layer/gesture brief)
1. Chrome markup only inside `{% block header %}` / `{% block nav_chrome %}` / `{% block footer %}`, which base wraps in `is_web()`; add the root to `tests/Navigation/NavChromeAssertions::WEB_CHROME_SELECTORS` and a native-UA row (`tests/Navigation/NativeUserAgents`). The Menu selector is `#site-menu:not(main #site-menu)`: the `menu` page renders the partial inside `<main>` (also in the app) and asserts `main #site-menu` positively (F26).
2. Flags read only through `assets/platform.js` (`isNativeApp()`, `nativePlatform()`, `os()`, `isStandalone()`); never `window.isNativeApp`, `dataset.*` or UA strings; CSS uses `html[data-native-app]` / `[data-os=…]` / `html.is-standalone`.
3. Layer openers are `<a href>` to the plain route; frame openers use `data-turbo-frame="{{ layer_frame('modal-frame') }}"`.
4. Gesture/animation/restore decisions are pure exported functions taking `nativeApp`, returning the neutral result in the app; add a row to `tests/native-step-aside-harness.mjs` and the file to `NATIVE_AWARE_MODULES` (`tests/PlatformFlagReadersTest.php`).
5. Haptics only via `haptic(name)`.
6. Head scripts in `assets/head/*.js` (ES5, page-independent text, inlined by `templates/_head_flags.html.twig`, return early under `data-native-app` except `platform_os.js`); never between `msp-rendered-at` and its script.
7. Critical CSS zeroes every reserved chrome size under `html[data-native-app]`.
8. Nothing makes a native response `public`; explicitly public endpoints never branch on the platform; streams rendered without a request never call `is_native_app()`.
9. Copy about ☰/tab bar/"top right" renders only under `is_web()`.
10. Top-bar tools carry `data-bar-action="{{ bar_action('…') }}"`, an accessible name and a real `href`; Inbox also `data-bar-count`.

### 3.6 Translations
- Navigation chrome/Menu/registry keys under `nav.*` (`nav.bar.*`, `nav.account.*`, `nav.group.*`, `nav.row.*`, `nav.desc.*`, `nav.syn.*`, `nav.menu.*`, `nav.search.*`, `nav.launch.*`); moderator/admin Menu rows under `nav_admin.*` (English in every locale, one allow-listed prefix). Page features keep page namespaces (`inbox.*`, `help.*`, `community_page.*`, `where_did_it_go.*`, `add_intro.*`, `player_results.*`, `player_overview.*`, `players.card.context.*`, `confirm_dialog.*`, `edit_profile.preferences.*`, `hub.feed.*`, `stopwatch.pill.*`, `puzzle_add.tools.*`). Old `menu.*` and `footer.*` keys stay (legacy labels, LAUNCH-02 old names); only `menu.new_badge` is removed (F-05).
- All 6 locales in the same commit (de "Sie", fr "vous", es "tú", cs as surrounding keys). No value equal to English unless allow-listed (`tools/translation-same-as-english.php`: de "Community", de/es/fr "Puzzles", cs/fr "Menu", prefix `nav_admin.`).
- **Insert keys as text, never re-dump a YAML file** (en: 4-space bare keys; cs/de/es/fr/ja: mostly 2-space quoted). Before commit compare `parse(index) + fragment == parse(working tree)` per locale and run `lint:yaml translations`.
- Parallel agents return `var/navigation-delivery/translations/<ID>.yml` (nested keys, leaf = `{en, cs, de, es, fr, ja}`); the orchestrator merges.
- Stimulus texts via data attributes or `browser_translation()`; streams rendered without a request carry numbers only.

### 3.7 Budgets
- P0-02 pins are exact (`assertSame`) and only go down; every change carries a comment naming the requirement ID. "Budget unchanged" = ≤ the pin.
- **INB-02 lowers every exact signed-in pin by 1 in its own commit** (two unread counts → one statement), commented "INB-02".
- Chrome adds 0 statements per page view: everything rides on the profile row, the Inbox badge statement or the memoised `admin_queue_counts()` (one per page, moderators/admins).
- Endpoint budgets = "≤ N more than an empty signed-in endpoint measured in the same test": trait `tests/Navigation/EmptySignedInEndpoint.php` (created by MENU-01, reused by CARD-06) measures `GET /en/help` with `Turbo-Frame: modal-frame` as a signed-in player and asserts its SQL list is exactly {user refresh, profile row} before using it as the baseline.
- A pin may rise only when a main merge caused it: re-measure on the synced main, comment "moved by main <hash>", log it.

### 3.8 Test DB and tools
- **Inside the delivery worktree** every phpunit/paratest run uses `speedpuzzling_navsuite_test` (the tools' default: `var/navigation-delivery/tools/phpunit.sh -- tests/…`), and phpunit runs **one at a time** (orchestrator decision in `state.md`). `tests/.database.cache` is per worktree, not per DB, so a second DB name in the same worktree would be skipped as "current" and never created.
- **Agents in their own worktree** (`isolation: "worktree"`) use their own `speedpuzzling_<name>_test` with their own `docker run` (the tools hard-code the delivery worktree: mount *their* worktree at `/app`, same image/network/env), and delete their worktree's `tests/.database.cache` before the first run.
- Never point phpunit at the clone `speedpuzzling_nav_test` (the bootstrap drops the DB it is given).
- Focus-dependent WebDriver checks (NAV-03 "focus inside the header", NAV-08 keyboard, NAV-11 visible focus) call CDP `Emulation.setFocusEmulationEnabled {enabled: true}` through `navlib` first and assert `document.hasFocus()` (the Xvfb window may not have focus; F18). Timings below ~100 ms are measured in the page (`performance.now()` in a capture listener + `MutationObserver`), never through WebDriver round trips.
- ParaTest only at phase gates (`paratest.sh`, `speedpuzzling_navsuite_test`); drop `_1…N` and `_template` afterwards (flip `datistemplate` first).
- WebDriver checks live in `var/navigation-delivery/scripts/checks/<ID>.py` on `scripts/navlib.py` (P0-02), never committed.

### 3.9 Read models, registry, canaries
- New SQL read models live in `src/Query/` (top level — `BlocklistQueryCoverageTest` scans only there); memos/assemblers live in `src/Navigation/` (with `ResetInterface` when they hold state).
- Every new player-listing surface gets rows in `BlocklistCanaryTest`, `PrivateProfileCanaryTest` (+ `DraftCanaryTest` / `PlayersPageCanaryTest` where they apply); append-only `yield`s, one item at a time.
- New destinations get a `NavigationRegistry` entry in the same commit (menu stream owns the file; other items return a snippet). The structural registry test refuses entries for routes that do not exist yet.

### 3.10 Guest caching
Guest HTML stays shared-cacheable: no CSRF token, session start, flash read or per-visitor content in guest chrome; per-visitor state only client-side (localStorage/sessionStorage). Every new guest-visible route has a test asserting `Cache-Control` contains `public`. Frame variants and native responses are never `public`.

### 3.11 Head order and critical CSS
`base.html.twig` head order is fixed: viewport → `_head_flags.html.twig` (GEST-09/NAV-03/NAV-13 scripts) → asset-failure script → `msp-rendered-at` meta + its script → critical `<style>` (incl. `templates/navigation/_critical_css.html.twig`) → stylesheet link. Media queries in Level 3 syntax: desktop = `(min-width: 768px) and (min-height: 501px), (min-width: 768px) and (pointer: fine)`.

### 3.12 Privacy
Screenshots and HTML dumps only under `var/navigation-delivery/` or a temporary `public/_nav-delivery/` deleted after use; grep staged diffs for real names before every commit; never copy figures from `var/navigation-research/` or the clone into committed files.

### 3.13 Doc notes
Each agent returns 1–5 lines of "doc notes" (what DOC-01 must say); the orchestrator appends them to `var/navigation-delivery/doc-notes.md`.

## 7. Help sheet transport (README §4.5)

- **The sheet is the dynamic modal's content.** Openers are links `<a href="{{ help_path() }}" data-turbo-frame="{{ layer_frame('modal-frame') }}" rel="nofollow">` (? phone tool, desktop Feedback, the Menu's Send feedback row, the end-of-page line, the footer's Send feedback). `help_path()` = `help?url=<relative request URI>` (bare on `help` itself). Without JS, in a new tab or in the native app (`layer_frame()` → `_top`) the same link opens the full page.
- **`help` route** (HELP-01a): `Turbo-Frame: modal-frame` → only `help/_frame.html.twig` (`<turbo-frame id="modal-frame">`, no layout, no Menu), `private, no-store`, `Vary: Turbo-Frame`; otherwise the full page `help/page.html.twig` (`noindex, follow`, guest `public`, `Vary: Turbo-Frame`). `?url=` is untrusted: `HelpPageContextFactory` accepts a relative path (`ReturnUrl::tryFrom()`) or an absolute URL on the request host, matches it through the router, and never echoes it into an `href`; robots.txt disallows `help?url=` variants.
- **Content root:** `data-modal-size="" data-modal-sheet data-modal-scrollable data-modal-history data-controller="bottom-sheet help-sheet"` + handle, title, ×, rows from `HelpSheetBuilder` (registry). `data-modal-history` makes the dynamic modal take a `layer_history` entry (Back closes; swap when opened from the Menu — the Menu closes and drops `inert` before the modal shows; the modal sits above the Menu shell in the z-index scale). GEST-02 gives swipe-down on phones; `help_sheet_controller.js` keeps the draft (sessionStorage `msp:feedback-draft`) and focuses the textarea on `shown.bs.modal`.
- **Feedback form** (signed-in): `form_start(feedback_form, {action: path('feedback'), attr: {'data-turbo-frame': 'modal-frame'}})` — explicit action. `FeedbackController` stays on its `modal-frame` path: frame POST invalid → `help/_frame` with errors (422 via `FormInterface`); valid → dispatch `CollectUserFeedback` (absolute page URL rebuilt from the context for the mail), then `help/_frame` in its **sent state** (confirmation + Close + Send another; other rows unchanged), 200 (frame answers are exempt from the full-page rule). Full-page POST: valid → flash + 302 to the attached page (if `ReturnUrl` accepts it) else `help`; invalid → 422 full page. GET `feedback` → 302 `help?url=` (route kept); GET with the frame header → the help frame. Guests: no form, "Sign in to send feedback" → login with `?return=` the help full page and the same `url`.
- **Scrim and HELP-05 (R6, narrowed by F6/F7, decision 6):** the 34 existing `modal-frame` partials are **unchanged** — they keep Bootstrap's backdrop and outside-click close. Only the Help sheet takes its own-scrim path: every help opener carries `data-modal-scrim="own"` (from `help_opener_attrs()`); `dynamic_modal_controller.js` sees the trigger in `handleBeforeFetch` (`findTrigger()`), before the spinner path calls `show()`, and re-creates the instance through public API (`this.modal.dispose(); this.modal = new Modal(el, {focus: false, backdrop: false})`), draws its own scrim element (`.dynamic-modal-scrim`, closed state `display: none`, ends at `--bottom-nav-height` on phones), and handles outside clicks on the `.modal` element itself (`event.target === this.element` → `requestClose`; the `.modal` covers the scrim at z 1055, so the scrim never receives clicks); the default instance (`{focus: false}`, Bootstrap backdrop) is restored on `hidden.bs.modal`. The sent state calls the controller's `release()`: scrim hidden, `.modal { pointer-events: none }` with `.modal-content { pointer-events: auto }`, `body.modal-open` and the inline `overflow`/`padding-right` removed, `aria-modal` removed (the sheet is deliberately non-modal now). No Bootstrap private API is used (the modal already runs `focus: false`, so there is no Bootstrap focus trap; focus containment stays the controller's job, F7). Result: HELP-05 reads `.modal-backdrop === null` after send and a page link click navigates (a replace visit through rule (d)); HELP-01b sees the confirmation in place; ×, Esc, swipe and Back still close through the helper. HELP-05 step (a) reproduces the old bug first; if its root cause lies in the general close path, it is fixed there for every partial (HELP-05 (a)). A test asserts every rendered link to `help` carries `data-modal-scrim="own"`; a WebDriver check confirms outside-tap close still works on three non-help partials (result detail, edit time, achievements).
- **Links out of the sheet** (FAQ, guides, language, sign in) carry `data-turbo-frame="_top"` and become replace visits (rule (d)); "Suggest a correction" stays inside the frame (same layer and entry); "Reload page" (standalone only) = `layer_history.closeThen(() => location.reload())`.
