2. **Stay current with main.** `main` keeps moving while you work. At every phase gate (and once before QA): `git -C $M fetch origin`; if `origin/main` moved, merge it into `feature/navigation-redesign` inside the worktree (`git -C $W merge --no-ff origin/main`), resolve conflicts in favour of keeping both sides' behaviour, re-apply the clone's migrations if new ones arrived (§2.2), re-run composer/npm in the worktree if a lock file changed (§2.3), and re-run the gate. Record each sync (commit range) in the run log.
3. **Finish on the branch — never merge into main, never push.** At the very end (after QA and a last sync with `origin/main`, all gates green on the branch HEAD), leave `feature/navigation-redesign` as the deliverable and report for Jan, in the final report and in chat, the exact commands to ship it: `git -C /Users/janmikes/www/speedpuzzling.cz push -u origin feature/navigation-redesign` and `gh pr create --base main --head feature/navigation-redesign …` (or a local `git merge --no-ff feature/navigation-redesign` from a clean `main`). Also: if the main checkout's untracked spec copies (`git -C $M status --short docs/features/navigation` shows `??`) are byte-identical to the "Navigation redesign: spec" commit, delete them so a later merge or checkout of main does not trip over untracked files; if they differ, leave them and say so in the report.
4. **Commit hygiene** (even in the worktree): run `git status --short` and `git branch --show-current` before every commit; stage nothing before commit time; delete with `rm`, never `git rm`/`git mv`; commit with `git add -- <paths> && git commit -m "<IDs>: <summary>" -- <paths>`; `git diff --cached --name-only` must list only your paths; every commit message ends with the attribution trailer given in the session's system instructions (if any); for YAML translation files compare the parsed key→value maps of the index and the working tree before committing. 6. **Privacy.** The clone contains real player data. Never put business numbers from `var/navigation-research/` into committed files (the repo is public).

If an item is impossible without reversing a decision, mark it `blocked: <reason>` with 2–3 options and continue with independent items.
8. **Evidence or it didn't happen.** An item becomes `verified` only after *you* ran its Verify in the delivery environment (or re-ran the decisive command of a subagent's check) and wrote the evidence into `state.md`. Never skip, weaken or delete tests to get green; budgets may only go down.

After creating a session set the window rect, read `innerWidth` and adjust the rect by the difference until `innerWidth` equals the target. Every width-dependent check (NAV-03, NAV-04, NAV-13, QA-01) asserts `innerWidth` first — at 1280 and 1440 a few pixels flip the tier.

   - **Timing below 100 ms** cannot be measured through WebDriver round trips; measure inside the page (`performance.now()` + `MutationObserver`, GEST-04).
   - **No CDP events over HTTP.** `goog/cdp/execute` is request/response only (no `Network.*` / `Fetch.*` event stream). Observe requests with Resource Timing (`performance.getEntriesByType('resource')`, `initiatorType: 'fetch'`), reloads with the probe (`window.__navProbe`, `performance.timeOrigin`), console errors and haptics with recorders registered before navigation (`Page.addScriptToEvaluateOnNewDocument`), slow responses with an in-page `window.fetch` wrapper. Touch input: `Input.dispatchTouchEvent`.
   - **iOS user agent in Chromium.** Override with `Emulation.setUserAgentOverride` including `userAgentMetadata.platform: 'iOS'` (or no Android client hints), then assert `<html data-os="ios">` before any iOS-branch check — Pixel emulation alone reports Android client hints.
   - **Back-forward cache.** Before any GEST-14 check, a control page must show `pageshow.persisted === true` after a full navigation and Back; otherwise run the synthetic `PageTransitionEvent` variant of GEST-14 and record "real bfcache: inconclusive".
