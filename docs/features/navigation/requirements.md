# Navigation redesign — requirements

Every item has an ID, **Done when** (the outcome) and **Verify** (an objective check a fresh agent can run). Decisions and reasons: [`README.md`](README.md) (D1–D22). Progress and evidence: only in [`delivery/state.md`](delivery/state.md). An item is `verified` only when its Verify ran in the delivery environment and the evidence is recorded.

## Conventions (apply to every item)
- Follow `CLAUDE.md`: single-action controllers; state changes only via Messenger handlers; repositories never flush; `ClockInterface`; services caching per-request data implement `ResetInterface`; migrations generated with `doctrine:migrations:diff` against a scratch DB built from committed migrations, additive and nullable/defaulted only; Turbo rules (explicit `action:` for forms in `modal-frame`, full-page form POSTs never answer 200); `json_ld` filter; exceptions logged with `'exception' => $e`.
- Every user-visible string is a translation key in all 6 locales (en, cs, de, es, fr, ja) — German formal "Sie", French "vous", Spanish "tú", Czech as surrounding keys. No new key's value may equal its English value in another locale unless it is a proper noun or allow-listed (e.g. "Community" in German).
- **No new SQL statement per page view** for chrome (bars, badges, pill, pointers, Menu) beyond the P0-02 budgets. Budget tests: numbers may only go **down**, each change commented; "budget unchanged" in a Verify means "≤ the pinned value". Endpoint budgets are stated as "≤ N statements more than an empty signed-in endpoint measured in the same test" (budget tests count every statement of a request, including the user refresh, the profile row, the Inbox badge and the announcement claim). Failing old-markup tests are updated to the new markup with the same intent, never deleted or weakened.
- Every new service under `src/Navigation/` that holds mutable properties implements `ResetInterface` (FrankenPHP worker mode; the delivery web server is `php -S`, where leaks cannot show) — asserted by one test that reflects over the directory.
- Every new or changed player-listing surface is added to `tests/BlocklistCanaryTest.php` and `tests/PrivateProfileCanaryTest.php` (and `DraftCanaryTest`/`PlayersPageCanaryTest`/coverage tests where they apply).
- Guest (anonymous) HTML stays shared-cacheable: no CSRF token, session start, flash read or per-visitor content in guest chrome; guest responses keep `Cache-Control: public`.
- No route is removed or renamed; old URLs keep working (redirects where the content moved).
- New routes have paths in all 6 locales (hreflang follows).
- Screenshots and HTML dumps live under `var/navigation-delivery/` (git-ignored) or a temporary `public/_nav-delivery/` deleted after use; never committed (dev data contains real names).
- "Phone" = < 768 px or a landscape phone (`(pointer: coarse) and (max-height: 500px)`); "desktop" = everything else. CSS writes the desktop condition in Media Queries Level 3 syntax: `(min-width: 768px) and (min-height: 501px), (min-width: 768px) and (pointer: fine)` (README §4.3).
- **Native app vs device OS.** Two different flags, never mixed: `<html data-native-app>` (server-rendered from `is_native_app()`, README §4.14 — inside the Hotwire Native app; JS `isNativeApp()`) and `<html data-os="ios|android|other">` (client-only head script, README §4.13 — the device's OS in any browser; JS `os()`). Both are read only through `assets/platform.js`. Everything web-only steps aside inside the app; haptics only through `haptic(name)` (`assets/haptics.js`); the existing `platform-*` / `native-app` classes keep meaning "inside the app".
- **Browser checks run without devices**: in the delivery Selenium Chromium (raw WebDriver + CDP through `goog/cdp/execute`, orchestrator prompt §2.6); Playwright Chromium (new headless) and WebKit (iPhone 15 profile) are optional extra evidence — a step only WebKit can run is recorded `n/a (no WebKit)` when Playwright is unavailable and never blocks `verified`. Device-only facts go to QA-06. Terms: **Pixel emulation** = `mobileEmulation: {deviceName: 'Pixel 7'}`, or `deviceMetrics` at the width a check needs with the Pixel 7 user agent; **iOS UA** = the same with an iPhone Safari user agent and UA-CH metadata without Android (CDP `Emulation.setUserAgentOverride` with `userAgentMetadata.platform: 'iOS'`), asserting `data-os="ios"` before any iOS-branch check; **desktop** = no emulation; **haptics recorder** = a script registered before navigation (CDP `Page.addScriptToEvaluateOnNewDocument`) that replaces `navigator.vibrate` with `p => ((window.__vib = window.__vib || []).push(p), true)`.
- **Reload and history probe** (used by every Verify that says "probe"):
  - before the action run `window.__navProbe = crypto.randomUUID()` and note `performance.timeOrigin` and `navigation.currentEntry.index` (Navigation API, available in the delivery Chromium);
  - opening a layer: `location.href` is unchanged and the index is +1;
  - after `history.back()`, ×, Esc, scrim or swipe-down: the layer is closed; `window.__navProbe` still holds the same value and `performance.timeOrigin` is unchanged (no reload, no navigation); `navigation.currentEntry.index` is back to the noted value; `location.href` is unchanged;
  - one more `history.back()` leaves the page: the URL becomes the previous page's.
  (`performance.getEntriesByType('navigation').length` and `history.length` cannot detect a reload or a correct close and are never used as evidence.)
- **Verify-after.** When an item's Verify names a layer, page or item that is built later, the item is set to `implemented (verify-after: <IDs>)` with evidence of what could already run. It becomes `verified` in the phase of the last named ID, when its full Verify is re-run. Each layer item (MENU-02b, HELP-01b, CARD-01a, NAV-03's search view, NAV-13's overlay) re-runs the GEST-01 layer checks (and GEST-02 for sheets) for its own layer. A phase gate passes with such rows listed.

**P0-03 Navigation click instrumentation (current navigation first).** Every link/button in the nav partials (and later the new ones) carries `data-nav="<surface>/<place>/<item>"` (`^[a-z_]+/[a-z_]+/[a-z0-9_]+$`); one delegated listener dispatches a `msp:nav` DOM event, sends GA4 `nav_click` when GA is loaded, and `navigator.sendBeacon` to `POST /-/nav-click` (single-action controller; path + data-nav only; no cookies/session; logged on its own Monolog channel excluded from Sentry). - Done when: today's header/footer links all carry `data-nav`; the beacon endpoint logs one line per click, one viewport line per session and one line per Back/Forward navigation.
- Verify: render test (guest + member) that every `<a>`/`<button>` inside header/footer/nav partials has a well-formed `data-nav`; controller test for the endpoint (204, log entry; a malformed value is dropped); node or WebDriver checks that clicking a `[data-nav]` link dispatches `msp:nav` with `{surface, place, item}`, that a click elsewhere on the page sends nothing, that the viewport bucket is sent once per session (second page view: none) and that a `history.back()` sends one Back line; the commit hash recorded as "deploy separately".
